# DVC Benchmark

Results for the Digital Volume Correlation (DVC) feature in
`fiber_tracer.correlation.dvc`, covering accuracy validation, a voxelization-
fidelity sweep, and a cross-tool comparison. Generated by
`scripts/dvc_resolution_benchmark.py` and `scripts/dvc_tool_benchmark.py`;
run either script to reproduce or refresh the numbers below.

See [`RESEARCH_FOUNDATION.md`](RESEARCH_FOUNDATION.md) §8 for the literature
background, and
[`docs/superpowers/specs/2026-08-02-dvc-spike-design.md`](superpowers/specs/2026-08-02-dvc-spike-design.md)
for the feasibility spike that preceded this feature.

## Methodology

All results use the same known-deformation phantom approach: generate a
synthetic fiber phantom (`fiber_tracer.validation.phantoms.generate_fiber_phantom`),
apply a known rigid shift (2.5 voxels) composed with a known uniform uniaxial
strain (2%), then check how well each tool/configuration recovers the known
displacement/strain field. This is the same methodology validated in
`tests/test_deformation.py`.

Per `RESEARCH_FOUNDATION.md` ref 60 (Croom et al.), DVC accuracy is
scan/window/speckle-density dependent, not a fixed number — every real run of
this feature also computes a per-run noise floor (`estimate_noise_floor`,
correlating a volume against a copy of itself) rather than relying on the
numbers below as a universal guarantee.

## Accuracy vs. voxelization fidelity

`supersample` (the phantom generator's anti-aliasing parameter) does not
increase voxel-grid resolution — it averages `supersample³` sub-voxel samples
per voxel, reproducing the partial-volume effect of a real detector.
`supersample=1` gives hard/aliased fiber edges; higher values give smoother,
more realistic boundaries closer to a well-resolved real scan.

| Supersample | Convergence rate | Displacement error (voxels) | Strain error |
|---|---|---|---|
| 1 | 92.6% | 0.4767 | 0.0054 |
| 4 | 85.2% | 0.2909 | 0.0046 |

Higher voxelization fidelity reduces both displacement and strain error, at
the cost of a small drop in convergence rate (more realistic partial-volume
blur makes a few borderline windows harder to converge). `supersample=8` was
attempted and found impractical for a routine benchmark (>13 minutes at this
phantom size); see the script's docstring for the measurement and reasoning.

## Cross-tool comparison

| Tool | Status | Convergence rate | Displacement error (voxels) |
|---|---|---|---|
| spam (this repo) | measured | 92.6% | 0.4767 |
| TomoWarp2 | evaluated, not integrated | n/a | n/a |
| Avizo (Thermo Fisher) | literature description, no live run | n/a | n/a |

**spam** is this feature's live backend (`fiber_tracer.correlation.dvc`),
measured directly.

**TomoWarp2** (open-source local DVC) was evaluated but not integrated: its
core correlation worker (`DIC_worker.py`) hard-depends on a SWIG-wrapped C
extension — not an optional accelerator, the only implementation of the
pixel-search step. That extension's `setup.py` uses `distutils.core`, removed
entirely from the standard library in Python 3.12, and building it also
requires the `swig` binary (not installed in this environment), on top of
~26 files of Python-2-only syntax (`print "..."` statements) across the
codebase. Porting it is a multi-day undertaking, well beyond this benchmark
task's scope — reported here as evaluated-not-integrated rather than skipped
silently.

**Avizo** (Thermo Fisher, commercial) has no license available in this
environment, so no live run was possible. Its DVC methodology — a two-step
local-then-FE-global correlation — is corroborated across vendor
documentation and independent papers citing it. No tool-specific accuracy
number is reported here: several searches for a specific, fetchable,
independently-verifiable published figure returned only paraphrased/garbled
snippets or 403/timeout errors on the source documents, and per this
project's citation-integrity standard (every reference in
`RESEARCH_FOUNDATION.md` is fetch-verified), an unconfirmed number is not
worth including. The applicable literature accuracy context — equipment-
agnostic, not tied to any one tool — is Croom et al.'s interlaboratory DVC
Challenge update (`RESEARCH_FOUNDATION.md` ref 60): 0.012–0.043 voxel
displacement std dev achievable under good conditions, up to 0.5 voxel
machine-specific distortion depending on scanner/protocol.

**DICe and FIDVC were excluded from consideration entirely**, not just left
out of the table: DICe is a stereo-camera surface-DIC tool (2D images plus
triangulation), not volumetric CT-DVC, so it isn't a fair comparison against
volume correlation. FIDVC (Bar-Kochba et al., `RESEARCH_FOUNDATION.md` ref
55) is MATLAB-only with no Python implementation.

## Reproducing

```bash
pip install -e ".[dvc]"   # + `brew install gmp` on macOS
python3 scripts/dvc_resolution_benchmark.py
python3 scripts/dvc_tool_benchmark.py
```

Both scripts write JSON (and the resolution script also writes a markdown
table) to `benchmark_results/` (gitignored — regenerate rather than diff).
